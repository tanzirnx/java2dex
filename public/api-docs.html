API

Use java2dex from your own scripts

The same endpoints the web UI calls are open — no API key, no auth. Call them directly with curl, Postman, or any HTTP client. Rate limits are whatever Render's free plan allows; be reasonable.

POST/convert

Compile .java source (or a .zip of one) to DEX bytecode.

# basic — one file
curl -X POST https://https://java2dex.onrender.com/convert \
  -F "javaFiles=@MyClass.java" \
  -o classes.dex

# multiple files, compiled together
curl -X POST https://https://java2dex.onrender.com/convert \
  -F "javaFiles=@A.java" \
  -F "javaFiles=@B.java" \
  -o dex-output.zip   # .zip only if multidex output

# a .zip project (auto-extracted server-side)
curl -X POST https://https://java2dex.onrender.com/convert \
  -F "javaFiles=@project.zip" \
  -o classes.dex

# with manual multidex control
curl -X POST https://https://java2dex.onrender.com/convert \
  -F "javaFiles=@MainActivity.java" \
  -F "mainDexClasses=MainActivity,MyApplication" \
  -F "minApi=19" \
  -o classes.dex
FieldTypeNotes
javaFilesfile(s)One or more .java files, and/or a single .zip. Repeat the field for multiple files.
mainDexClassestextOptional. Comma/newline-separated class names to force into the primary dex.
minApitextOptional. Passed to d8 as --min-api.

Response (success): binary — classes.dex if one output file, else a .zip. Useful headers:

HeaderMeaning
X-Compiled-Class-CountNumber of classes compiled
X-Compiled-ClassesURL-encoded, comma-separated class names
X-Dex-File-Count1, or more if multidex
X-MainDex-Matched / X-MainDex-UnmatchedOnly present if mainDexClasses was sent

Response (error, 400/500): JSON — { error, details, parsedErrors }. parsedErrors is an array of { file, line, level, message } when javac output could be parsed.

POST/decompile

Decompile .dex / .apk / .jar / .class / .aar back to Java source.

curl -X POST https://https://java2dex.onrender.com/decompile \
  -F "inputFiles=@classes.dex" \
  -o decompiled-sources.zip
FieldTypeNotes
inputFilesfile(s)Up to 5 files, 60MB each. .dex, .apk, .jar, .class, .aar, .zip.

Response (success): decompiled-sources.zip, plus header X-Java-File-Count. Errors: same JSON shape as /convert.

POST/java-to-smali

Compile .java source all the way to disassembled Smali (javac → d8 → baksmali).

curl -X POST https://https://java2dex.onrender.com/java-to-smali \
  -F "javaFiles=@MyClass.java" \
  -o smali-output.zip
FieldTypeNotes
javaFilesfile(s)Same as /convert — .java files and/or a .zip project.

Response headers: X-Smali-File-Count, X-Method-Count, X-Field-Count (vs the 65536-per-dex limit), X-Smali-Preview (URL-encoded text of the first file).

POST/smali-to-dex

Assemble .smali source (edited or otherwise) back into a DEX file.

curl -X POST https://https://java2dex.onrender.com/smali-to-dex \
  -F "smaliFiles=@MyClass.smali" \
  -o classes.dex
FieldTypeNotes
smaliFilesfile(s).smali files, and/or a .zip containing them.
GET/health

Liveness check — useful for uptime monitors or waking a sleeping free-tier instance.

curl https://https://java2dex.onrender.com/health
# {"ok":true}

Replace https://java2dex.onrender.com with your actual Render URL. Everything above is exactly what the web UI itself calls — nothing hidden.
